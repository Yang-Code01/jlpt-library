# 《Pi 工具链手册》走「结构化真源 → 整页生成」，校验器自带十条可失败断言

Status: accepted

`tools-dev/pi-toolchain.html` 是一页讲清「本机 pi 装了哪些包、命令与配置在哪、有哪些技能与内置工具、哪些文档根本没写」的手册。它的内容真源是 `tools-dev/pi-toolchain.data.json`：`node tools/pi-toolchain-gen.mjs` 生成整页（数据与样式全部内联，`file://` 直接可开），`check` 重跑生成并与仓库成品逐字节比，再对成品跑十条断言（条目不丢、锚点不死、无泄漏、行尾 LF、无取数、出处可达、折叠守恒、缺口不静默、版本表一致、无 JS 不白屏）。`probe` 只探测本机 pi 安装，找不到退出 2，`tools/test.mjs` 据此把这条校验标 SKIP。

选这套而不是手写详情页，是因为这一页要覆盖 11 个包、约 340 行清单表、近 90 条命令，手写必然漂移，而漂移在这类页面里几乎无法肉眼发现：漏一个包、锚点指向已删小节、出处失效、版本表比真源旧一行，都不会让人看出「这页在骗我」。交给真源之后，这些都能变成退出码。

与 `research/` 报告（ADR-0003）的区别：报告是「一篇一篇成品」，手册是「一份真源一张表」；报告的外壳由 add-shell 注入，手册不套外壳、直接挂在工具开发区清单里（`tools-dev/data.json` 一条无 `dir`/`download` 的纯文档页记录）。

## Considered Options

- **手写详情页**：否决——340 行表格的漏条目与死锚点没有任何机制能发现。
- **正文手写 + 只把版本表做成标记区**：否决——`wb:report-list` 那种标记区只护住一小块；正文仍是漂移源。
- **运行期取 `data.json`**（`file://` 下不可能）：否决，全站硬约束禁 `fetch`。
- **把每条内容拆成独立文件、构建期合并**：否决——收益是并行编辑，代价是一个包要开一个文件，读者与维护者都要在两处之间跳。
- **断言只做「生成物 == 重渲染结果」**：否决——那只证明「没人手改」，证明不了页面本身说对了。十条断言里有一半是针对内容语义的（A6 出处可达、A7 折叠守恒、A8 缺口不静默、A9 版本表一致）。

## Consequences

- `tools-dev/pi-toolchain.data.json` 是唯一真源；`tools-dev/pi-toolchain.html` 是生成物，不许手改。生成器写在 `tools/` 并接进 `tools/test.mjs`（`CHECKS` + `SUITES` 两处）。
- 脱敏是机制而不是纪律：真源里只写可逆占位符（`~/`、`<PI_HOME>`、`<PI_CORE>`、`<REPO>`、`<USER>`），生成器不做替换；`check` 的 A3 扫全页，A6 才把占位符还原成真实路径验存在性——所以页面可以公开，校验仍能落到本机。
- 缺本机安装时不许伪装成通过：`probe` 退 2 → `DEP.plugins` 不满足 → 整条校验 SKIP 并打印原因；`check` 里的 A6 也自报跳过。
- 折叠阈值（单条目声明量 > 30）由 A7 与测试双向钉住：过阈必折、未过不折、折叠前后行数守恒。
- 「文档未载 / 两处矛盾」是一等公民：十八处 pi 官方文档之间的冲突与空白逐条入账，取舍列写「未替读者取舍」而不是编一个结论。
- 真源 schema 在实施中长出了两样 spec 没写的东西，两者都记在这里：`kind: "core"`（pi 自身命令面要归到自己一节）与 `tableHead`+`rows`（69 个技能与 338 行清单如果一行一张卡，页面就不可扫读）。它们不改变「真源 → 生成 → 断言」的结构，只多了一种条目形状。
- 已知局限：清单表格里的出处是文本（`docs/cli.md:282` 这种），A6 只验条目级出处；散文型出处（「四份文档均未给默认值」）无法验存在性，`check` 会打印跳过了多少处、以及多少行清单出处属纯文本（当前 265 行）。
- 升级流程固定为三步：改真源 → `node tools/pi-toolchain-gen.mjs` → `node tools/test.mjs`。页内也写了一节「这份页怎么更新」，供不读 ADR 的人用。
