# 门户加第四区「斯诺克信息」：进度图只讲当前站，数据靠定时生成的一份静态快照

Status: accepted

用户要的是「赛季走到哪儿了 + 世界排名」——一件**看**的事，不需要登录、不需要操作。于是加第四区，`data-area="snooker"`，与另三区平级。四条决定：

1. **进度图选「阶段跑道」，只讲当前这一站。** 做过六个能真打开的样张比选：整季甘特表（信息全但 19 行 ~600px 高）、赛季表盘（最像作品但环上认不出字）、节奏条（最省地但站名放不下）、对阵漏斗（换成场次口径，会漂移出日历）、以及两个合体版。用户选定「阶段跑道」：赛事头 → 轮次链（128 强到决赛）→ 七日条 → 剩余人数 + 下一站倒数，约 320px 高。理由：这个页面被看的时机是「今天有没有球、打到哪儿了」，而**休赛期**才是它最常出现的状态——那时整块退化成「赛季进度 + 下一站倒数」，正好和日历形态互补。
2. **数据是抓取侧生成的静态快照，页面侧只读。** `tools/snooker.mjs` 抓 snooker.org 的三张服务端渲染表（`template=31` 排名 / 2 赛历 / 7 冠军），写成 `assets/snooker-data.js` 里的 `window.SNOOKER`。用 `.js` 而不是 `.json`：站点必须 `file://` 双击能开，那时 `fetch('*.json')` 会被 CORS 拦死，而 `<script src>` 不受此限。页面里**不允许出现 `fetch`**，由 `tools/test.mjs` 的 `guardNoFetch` 守着。
3. **每 10 分钟跑一次，没变就不提交。** `.github/workflows/snooker.yml` 用 `cron: '*/10 * * * *'`（GitHub 的最小粒度是 5 分钟）；生成器比对「除 `updated` 之外的载荷」，相同就不写文件；workflow 再看 staging 是否为空，空则不产生提交。这样提交历史里只有真变动（排名换位、赛果落地），不会一天一百多条「更新时间」噪音。为什么这么密：snooker.org 的排名在赛事结束当晚就会变，而 GitHub 的 schedule 是尽力而为（整点前后会延迟、负载高时可能丢排队），10 分钟一次实际到点误差仍有几分钟到几十分钟。空转的成本为零（公开仓库的 Actions 免费），代价只是 Actions 面板里记录多。
4. **「最近完赛 / 接下来」两栏换成一根可拖动的赛季轨道。** 竖线按时间串起前后各 4 站，指针靠近时按距离衰减放大（`scale = 1 + 0.62·(1-d/104)²`），右侧详情随指针换（冠军 / 今日轮次 / 签表），按住可拖动、松手吸附最近一站，`↑↓` 也能切。理由：两栏列表只能「读」，轨道能「扫」——从「哪一站」到「谁赢的、打到第几轮」只多扫一眼，且不必为两个列表各留高度。窄屏（<700px）前后各收成 3 站，否则详情会被推到屏幕外。
   > **修订（2026-10-18）**：轨道从「前后各 4 站 + 可拖动 + 指针靠近即切」改成「整季 22 站 + 点击才切 + 指针只出摘要气泡」。原因：`pointermove` 直接 `paint()` 意味着从页面顶部移到天梯图的路上必然扫过轨道，内容跟着指针乱跳，滚轮滚轨道也会切站——用户在真实页面上报的就是这个。做过三个能真打开的样张比选（纯点击 / 驻留 0.62 秒预览 / 摘要气泡），用户选气泡：零误切换、同时保留「不用点就能比较各站」的能力。距离衰减放大（`scale = 1 + 0.62·(1-d/104)²`）保留，但它现在只是视觉提示，不再触发切换。

5. **排名口径按官方原文，不加工。** 两年滚动积分（旧奖金到期会扣，名次会「莫名」下滑）；显示 Top 16 常驻 + 展开全部 + 中国球员高亮 + ± 名次变动（本次抓取相对上次）+ 搜索框。上游允许并列（末尾 0 分选手会并列 125、127），照原样显示，不做「补号」。

## Considered Options

- **页面运行时调 `api.snooker.org`**：否决 —— 该 API 实测 `403.502`（IIS Dynamic IP Restrictions，按源 IP 封），换 UA / Accept / Referer 全部无效；且站点离线直开的约束本来就不允许运行时请求。
- **抓 `wst.tv`（官方站）**：否决 —— Nuxt 单页应用，`wp-json` 与日历页返回的都是 6 KB 外壳 HTML，服务端没有数据。
- **拿 calengoo 的 ICS 镜像当主力源**：否决，降级备用 —— 它只有赛程（没排名），`DTEND` 还需减一天，`DESCRIPTION` 里才有赛事类型；作为赛历抓不到时的兜底更合适。
- **整季甘特图 / 表盘当主形态**：否决 —— 见上，占高与可读性都不匹配「今天有没有球」这个主问题；它们更适合当「赛季总览」放在别处。
- **用 `.json` + 本地小服务器**：否决 —— 站点至今 `file://` 直开、零构建，为一张表引入 server 是倒退。
- **中文名/赛事名机翻**：否决 —— 人名音译翻法不统一（`Zhao Xintong` 赵心童 / 赵鑫童），用手维表 `CN_NAME` / `CN_EVENT` / `NAT_CN`，查不到就回退英文。

## Consequences

- 加区只动了这些地方：`index.html` 的 head 状态机（`PORTAL_SNOOKER_META` + `syncMeta` + `portalApplyArea` + 初始化守卫）、一条 `:not()` 显隐规则、一个 tab、一个 pane、约 150 行 `.snk-*` 样式、两个 `<script>`。没有新路由、没有新构建步骤。
- 失败策略不对称：**排名抓不到 = 中止**（exit 1，宁可不更新也不写脏数据）；**赛历 / 冠军抓不到 = `::warning::` 黄条 + 沿用上次赛历**，job 仍绿。上游挂了只会让排名更新停摆，不会把站点打空。
- 数据过期是静默的，所以页面头部把「最近一次抓取时间」写出来（`2026-10-18 01:06 UTC`），让人一眼看出这份快照有多旧。
- 本机抓不到（Cloudflare 403）：要跑生成器就得走 `127.0.0.1:18790` 代理，或者先 `curl` 存下三张页面再用 `--local / --local-cal / --local-fin` 离线跑。CI 上直连正常。
- 将来要加「单赛季排名」或「赛事详情」，数据侧往 `window.SNOOKER` 里加字段即可，渲染侧不必改抓取逻辑。
