# 听力每题一份注音讲义 PDF：生成器留在本地，只把成品入库

Status: accepted

用户要的是「点开这道听力题，就能下载一份带假名的讲义，原文、译文、生词、语法都在里面」，并且这份讲义要能覆盖 2021.07 全部 30 题（不能只做一题的手工特例）。于是有了这组决定：

1. **一题一份 A4 PDF，注音逐字标注。** 讲义结构固定七节：01 听力原文（每个汉字上方 ruby）、02 中文译文（逐句对照）、03 答案与解析（正解卡片 + 选项中文对照 + 干扰项解析）、04 高频生词（12–17 条，含例句）、05 高频语法（5–7 张卡片，接续/意义/例/注意）、06 听力策略（按题型给 3 步，敬语多时附「普通形・尊敬語・自謙語」对照表）、07 跟读与背诵（3 步 + 勾选句 + 3 分钟自测）。前四节来自题库数据，生词例句、语法接续、解析、跟读句、自测题来自每题一条补充稿（`sup/s<N>.json`）。
2. **成品入库，生成器不入库。** PDF 是站点要下载的文件，放 `listening/data/N2/pdf/202107_<section>_Q<qNo>.pdf`，与音频 `202107_<section>_Q<qNo>.mp3` 同规则。生成器（`gen.mjs` + `ruby.mjs` + `template.css` + 每题补充稿）留在本地 `.scratch/listening-pdf/`：注音靠 kuromoji，词典 40MB，而本站的硬约束是 `file://` 双击即开、零依赖、无构建（ADR 系列里已反复确认）。把 40MB 词典塞进仓库或让站点跑 npm install 都不可接受；反过来，把 30 份 HTML 入库也只是把同一份体积换个后缀。**入库的判据是「用户要下载的文件」**，其余留在本地。
3. **字体栈把 Yu 放首位，Noto 兜底。** 同一页 A4 实测：Chromium + Skia 对可变字体 Noto Serif JP / Noto Sans JP 输出 **Type 3** 字形程序（无字形子集，6 页 1.37MB，≈230KB/页）；换成 Yu Mincho / Yu Gothic 输出 **CID TrueType 子集**，同尺寸测试页 197KB → 52KB。30 份讲义按前者约 40MB，按后者约 9MB。选型顺序：日文衬线 `"Yu Mincho","Noto Serif JP",serif`、日文黑体 `"Yu Gothic","Noto Sans JP",sans-serif`、中文 `"Microsoft YaHei","Noto Sans SC",sans-serif`。这只影响本机（Windows）生成时的字形选择，PDF 内嵌子集与平台无关。
4. **下载按钮由「卷 + 题号」推地址，不给题库加字段。** `listening/listening.js` 的 `handoutUrl(q)` 把 `data/<level>/audio/` 换成 `data/<level>/pdf/`，文件名 `<exam去横杠>_<section>_Q<qNo>`.pdf。这样 30 题不需要 30 处手工登记，改名/换卷也不会漏；代价是「文件缺了按钮仍然在」，所以补一条**齐套校验** `tools/listening-handout.mjs`（题号 → 文件名 → 存在 → 是 PDF → 体量合理 → 目录里无多余文件，含题号连续性、同节重名检查），接进 `node tools/test.mjs`。这条校验不依赖任何东西，克隆即可跑。
5. **H5 的两问共用音频，靠 qNo 区分。** 第 5 节第 2 段音频两个设问（`H5-2a` 问 1、`H5-2b` 问 2），题库里 2b 的原文/译文是中文占位符（「同質問1音频，完整原文见上一题」）。生成器在检测到占位符时借用前一题的原文**与译文**，并去掉题库问题行开头的「（同上题音频）」括注；文件命名用 `section + qNo` 而不是音频名，否则两份讲义会抢同一个 `202107_5_Q2.pdf`。
6. **分页靠 `break-inside/avoid` 串联，不靠强制分页。** 最初给 04 生词、07 跟读都加了 `break-before: page`，结果是「答案页只写了一半就翻页」「策略页独占一页、下一页只有自测框」——6 页里有两页是半空的。改成只对**卡片级**元素禁止拆分（`.answer`、`.quiz`、`.checklist li`、语法卡），让章节自然流动；页数从 6–7 页降到 5–7 页，且中段页面都填满（逐页墨迹占比从 2.6–4.1% 提升到 8–11%）。

## Considered Options

- **只做 Q4 一份手工讲义（已有成品）**：否决 —— 用户明确要「以这份 PDF 为模板，分别生成 2021.07 的其他题目」，手搓 30 份无法维护。
- **用 pandoc / LibreOffice 从 docx 转**：否决 —— 本机没有，且两件它都做不到：逐字 ruby（`<ruby>`）与「选项中文对照 / 干扰项解析」这类版式。
- **把注音做成注音文本（`漢字（かんじ）`）而不是 ruby**：否决 —— 行高翻倍、原文可读性下降；ruby 在 Chromium 打印里渲染稳定（已实测 `rt` 不参与行高塌陷）。
- **把 kuromoji 词典精简后入库**：否决 —— 需要覆盖 N2 全部汉字与词性，精简版会退化成「部分注音」，比没有更误导。
- **用音频名当 PDF 名**：否决 —— H5 两个设问共用 `202107_5_Q2.mp3`，会撞名（见决定 5）。
- **每题在题库数据里加 `handout:` 字段**：否决 —— 30 处手工同步，且无法防止「字段在、文件没了」；改成由命名规则推导 + 工具校验文件真实存在。
- **强制每章新起一页（初版）**：否决 —— 产生大量半空页（见决定 6）。

## Consequences

- 新增 `listening/data/N2/pdf/`（30 份 PDF，见提交体积），`.gitattributes` 已把 `*.pdf` 标为 `binary`。
- 新增 `tools/listening-handout.mjs`（`check` / `list`），并注册进 `tools/test.mjs` 的静态校验；CI 不生成 PDF，只校验齐套。
- `listening/listening.js` 增 `handoutUrl(q)`，题卡标题行右侧出现「↓ 注音讲义 PDF」按钮；`listening/listening.css` 增 `.q-head` / `.pdf-btn` 样式（窄屏收小）。按钮只依赖文件名规则，新增卷时**先生成 PDF 再上架**，否则点开是 404。
- 生成器与补充稿留在 `.scratch/listening-pdf/`（gitignored）：换机器/重装后要重做注音，需先 `npm i kuromoji` 放进该目录并在 `node_modules` 就位；补充稿是 30 题的人工产物，**删 `.scratch` 等于丢掉唯一副本**——若后续要长期维护，应把 `sup/*.json` 单独备份或另议入库范围。
- 注音规则不是纯词典直读：`ruby.mjs` 里有一层修正（方 ほう→かた、後 のち→あと、明後日→あさって、等 とう→など），以及数词+量词的合并表（一人 ひとり、二人 ふたり、一本 いっぽん…）。这些是按本卷 709 个汉字 token 全量审计后定的，换卷时需重新审计。

## 补记：第二卷 2025.07（2026-11）

同一套管线跑第二卷时的实情，留给下一次：

- **生成器已参数化**（本地 `gen.mjs`）：`--exam 2025-07 --level N2 --root <worktree>`；补充稿目录随之变为 `sup-<exam>/`（2021.07 仍是 `sup/`），输出文件名前缀 `<exam去横杠>`，页脚卷号由 `--exam` 推出。
- **补充稿按题型切片**：`sup-2025-07/g1..g4.json` 分别对应 問題1+2（11 题）、問題3（5 题）、問題4（11 题）、問題5（3 题）。切片中间稿在 `in-2025-07/g*.json`，字段与题库数据同形，交给子任务时不必再贴数据。
- **页数区间要放宽**：問題4 只有一句台词，讲义是 4 页；其余 5–7 页。`tools/listening-handout.mjs` 的 `TARGET_PAGES = [5, 8]` 只用于提示文案、不参与判定，所以 4 页的题不会被判失败。
- **2025.07 的题目来源不是 OCR 脚本**：原文取自 learnjp 的扫描 PDF（`pdftoppm` 后逐页人读 + whisper small 转写对齐），答案三源交叉（learnjp / aixinjp / PDF 的「答え」行）；問題4 网页答案与 PDF 逐题冲突时**以 PDF 为准**。
- **問題1/2 的选项换成了卷面原文**：最初流传的整卷音频（喜马拉雅）是单人重录、25 分钟删节版，原文 PDF 也只印「問題：／答え：」，四个选项无处可查，一度按原文动作重组并在题库 `note` 与讲义末尾标注（`listening.js` 的 `.q-note` 就是那时加的）。后来找到 YouTube「Choukai JLPT N2 7/2025」的考场原版录音（44:49，含「天気がいいから散歩しましょう」试音），其画面逐帧抄出 44 个卷面选项，同时用它重切 29 段音频——数据里的 `note` 随之删除，讲义也不再带那句声明。**现在这卷的选项与音频都来自真题本身**，`.q-note` 能力保留给以后的卷子。
- 注音层对第二卷没做逐 token 审计，只抽查了多音字（空/生/作/光/少/混/込/経/手/方/後/日/時/行/上/入/出/会/家）与整词（一人前 いちにんまえ、湖 みずうみ、砂浜 すなはま）——抽到的都对得上上下文。若将来发现错读，改 `ruby.mjs` 的修正表后**两卷都要重生成**。

## 补记：第三卷 2023.07（2026-11）

2023.07 卷沿用同一套七节版式与命名规则（`202307_<section>_Q<n>.pdf`），生成命令：

```
cd .scratch/listening-pdf && node gen.mjs --exam 2023-07 --root ../..
```

与首卷的差异：

- **原文/选项/答案的来源是真题卷面**：`learnjapaneseaz.com` 的「2023年7月N2听解原文与答案回忆版」11 页扫描图，問題1・2 的四个选项印在卷面，問題3・4・5-1 的选项在录音里念出，逐题与 `exam/data/N2/audio/202307_*.mp3` 的转写核对（`.scratch/listening-2023-07/asr-2023.txt`）。这套卷**没有「选项是整理出来的」这条声明**——卷面本来就有。
- **一处答案冲突**：問題1 5番的回忆版把红字标在 4「来場者の案内をする」，但录音原文是「封筒を各机に置いて準備は完了です」「当日は来場者の案内もお願いします」——今天要做的只有「机に封筒を置く」，故取 **3**（`exam/data/N2/2023-07.js` 也是 3）。记在这里是因为「回忆版红字」通常是最可信的单一来源，例外得留痕。
- **补充稿仍分两组写**：`sd-2023-07/gN.json`（学习页用的译文/单词/语法，由 `.scratch/listening-2023-07/build-data.mjs` 合进 `listening/data/N2/2023-07.js`）与 `sup-2023-07/gN.json`（讲义用），两边一起跑 `check-sup.mjs` 交叉校验（译文行数、例句逐字出现、覆盖关系）。
- **問題4 只有 4 页**：即时应答每题仅一句台词、三个三选项，天然短，`TARGET_PAGES` 只用于提示文案，不参与判定。
- 新增卷时仍需改 `tools/listening-handout.mjs` 的 `EXAMS`（现为 `['2021-07', '2025-07', '2023-07']`）并重跑 `node tools/test.mjs`。
